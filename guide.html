1.1 LabVIEW 的全称和含义

LabVIEW = Laboratory Virtual Instrument Engineering Workbench（实验室虚拟仪器工程工作台）。它由美国 NI（National Instruments，美国国家仪器）公司于 1986 年发布，是世界上第一款图形化编程语言。

🔑 核心理解：什么是「图形化编程」？

传统的编程语言（C、Python、Java）用 文字代码 写程序。LabVIEW 用 图形、方块和连线 来写程序——就像画电路图或流程图的思路。你不需要记忆语法、括号、分号，只需要把功能方块拖到画布上，然后用线把它们连起来。

1.2 LabVIEW 在实际工作中用来做什么？

LabVIEW 的核心战场是测试测量和自动化控制。以下是真实的应用场景：

行业具体做什么为什么用LabVIEW
🔋 电池/新能源电池充放电测试、容量标定、循环寿命测试、内阻测量、BMS 验证天生具备仪器通信、数据采集、曲线绘制能力，开发速度是C#的3-5倍
🏭 产线自动化ATE 自动化测试站（FCT/ICT）、产品出厂质量检测、不良品自动分拣支持所有主流仪器品牌驱动，快速构建测试序列
🔬 实验室科研温度/压力/振动/应变/电压/电流等多物理量同步采集与分析与NI采集卡（DAQ）深度集成，无需写底层驱动
🤖 运动控制伺服电机控制、步进电机定位、机械臂轨迹规划NI运动控制卡 + SoftMotion模块

2.1 LabVIEW 有哪些版本？我该装哪个？

版本类型说明适合人群
Community Edition（社区版）免费！功能完整，用于学习/个人项目/非商业用途✅ 学生、自学者、爱好者
Professional Edition（专业版）付费，商业用途，含 Application Builder 可生成 EXE企业、商业项目

学习建议：安装 Community Edition（社区版），完全免费且功能足够学完这本教材。去 NI 官网 ni.com 搜索 "LabVIEW Community Edition" 下载。建议选择 2020 或更新版本（推荐 2023/2024 Q1）。

2.2 安装步骤（Windows）

  1. 下载安装包：访问 ni.com → 搜索 "LabVIEW Community Edition Download" → 选择对应版本 → 需要注册 NI 账号（免费，用邮箱注册即可）
  2. 运行安装程序：双击下载的 ni-labview-xxxx.exe，如果弹出用户账户控制提示，点击「是」
  3. 选择安装组件：安装程序会让你勾选组件。初学阶段建议勾选：LabVIEW 主程序、NI-DAQmx 驱动（数据采集）、NI-VISA 驱动（仪器通信）、NI MAX（设备管理器）。其他可选组件可以先不装，以后可以随时补充安装。
  4. 等待安装完成：安装过程需要 20-60 分钟，取决于你的电脑性能和网络速度。过程中可能提示重启，按要求操作即可。
  5. 激活：社区版用 NI 账号登录即可激活，专业版需要输入序列号。
安装时建议关闭杀毒软件和防火墙，避免误拦截。安装路径建议使用默认路径（C:\Program Files\National Instruments\），不要改到中文路径。

2.3 安装后还需要装什么？

  3. 如果弹出许可证激活窗口，社区版用户用 NI 账号登录
✅ 启动成功标志：看到带有 LabVIEW 大 Logo 的启动窗口，左侧有 "New"、"Open" 等选项。

3.2 VI 的两个窗口：前面板 vs 程序框图

点击 "Blank VI" 后，你会同时看到两个窗口。这是 LabVIEW 最核心的设计——每个程序都由两个「面孔」组成：

特性🟫 前面板 Front Panel⬜ 程序框图 Block Diagram

给谁看给用户/操作员看和操作的给你/开发者看和修改的

🔑 理解：前面板和程序框图的关系

把前面板想象成一辆汽车的仪表盘（方向盘、速度表、按钮）——这是驾驶员（用户）操作的地方。把程序框图想象成发动机舱（引擎、电路、油管）——这是修车师傅（开发者）工作的地方。两个窗口通过 Ctrl+E 来回切换。

✍️ 第一个 LabVIEW 程序：从零写出 A+B=C

▼

4.1 目标

创建一个 VI：用户输入两个数字 → 点击按钮 → 程序计算两数之和 → 显示结果。虽然简单，但这会带你走完 创建控件 → 添加函数 → 连线 → 运行 的完整流程。

4.2 详细操作步骤

第1步：新建空白 VI

在 Getting Started 窗口点击 Blank VI，或使用快捷键 Ctrl+N。你会看到两个窗口：灰色前面板和白色程序框图。

第2步：在前面板上放置输入控件（两个数字输入框）

  1. 确保你在灰色前面板窗口（不在的话按 Ctrl+E 切过来）
  2. 在灰色区域右键 → 弹出控件选板
  3. 找到 Numeric → Numeric Control（一个带上下箭头的小数字框）
  4. 点击选中后，鼠标变成小手+控件虚影 → 在灰色面板上点击放置
  5. 你会看到一个标签为 "Numeric" 的数字输入框。双击标签文字，改名为 "输入A"
  6. 重复 2-5 步，再放一个 Numeric Control，改名为 "输入B"

第3步：在前面板上放置输出显示控件（结果显示）

  1. 右键 → Numeric → Numeric Indicator（和 Numeric Control 很像，但背景是灰色的，且前面板图标边框更细）
  2. 放置后双击标签改名为 "结果C"
Numeric Control（输入控件）和 Numeric Indicator（输出显示）的区别：Control 的边框较粗、背景白色，用户可以修改值。Indicator 的背景偏灰，用户不能直接修改值。在程序框图中，Control 的图标边框粗（数据源），Indicator 的图标边框细（数据接收端）。

第4步：切换到程序框图，找到对应的端子

按 Ctrl+E 切到白色程序框图。你会看到三个图标：两个边框粗的（输入A和输入B）和一个边框细的（结果C）。这些是在前面板放了控件后自动生成的端子。

第5步：添加加法函数

  1. 在白色区域右键 → 弹出函数选板
  2. 找到 Numeric → Add（一个三角形图标，上面有 + 号）
  3. 点击放置到程序框图中

第6步：连线 —— 这是最关键的一步

  1. 鼠标移到「输入A」图标右侧的小三角端子 → 光标变成线轴图标（表示可以连线了）
  2. 按住鼠标左键，拖动一根线到 Add 函数左上角的 x 端子 → 线连上了（橙色线）
  3. 同样方法，把「输入B」连到 Add 函数的左下角 y 端子
  4. 把 Add 函数右侧的输出端子连到「结果C」图标的左侧输入端
  5. 检查：如果所有线都是实线没有虚线，说明连线正确

🔑 连线颜色代表数据类型

橙色细线 = 浮点数（小数），蓝色细线 = 整数，绿色细线 = 布尔值，粉色细线 = 字符串，黑色虚线 = 错误连线（类型不匹配）。

第7步：整理程序框图

点击工具栏上的 Clean Up Diagram 按钮（扫帚图标），LabVIEW 会自动帮你整理连线和图标位置，让框图变得整洁。

第8步：运行验证

  1. 按 Ctrl+S 保存 VI，命名为 "加法器.vi"，放到桌面或你建的文件夹里
  2. 按 Ctrl+R 或点击 ▶ 运行按钮
  3. 在前面板的「输入A」中输入 5，「输入B」中输入 3
  4. 「结果C」应该自动显示 8
  5. 改一下输入值试试：A=3.14, B=2.86 → 结果应该等于 6.00
✅ 恭喜！你已经完成了人生中第一个 LabVIEW 程序。虽然只是一个简单的加法器，但你学会了：创建控件、切换到框图、添加函数、连线、运行。这是所有 LabVIEW 程序的基础骨架。

4.3 练习：自己动手改一改

  1. 把加法改成乘法（提示：用 Multiply 函数替换 Add）
  2. 改成三数相加（提示：需要两个 Add 函数，先加两个再加第三个）
  3. 加一个指示灯：当结果大于 100 时，绿色灯亮起（提示：用 Comparison → Greater? 判断是否 >100，结果连到 Boolean → Round LED）

5.1 数值控件（Numeric）—— 数字的输入和显示

数值控件是 LabVIEW 中使用频率最高的控件类型。所有的测量数据、计算结果、参数设置都通过数值控件来交互。

控件外观特点典型用途
Numeric Control白色背景 + 上下箭头用户可修改值，支持键盘输入和鼠标拖拽参数设置（电压值、电流值、温度阈值）
Numeric Indicator灰色背景只显示不可修改，程序运行时自动更新显示测量结果（当前电压、电流、温度）
Knob（旋钮）圆形旋钮模拟真实旋钮，旋转调整数值模拟仪器面板上的调节旋钮
Slide（滑块）水平/垂直滑杆拖动滑块改变数值，直观反映位置关系音量调节、范围选择
Gauge（仪表盘）半圆/圆形表盘指针指示数值，类似汽车速度表实时显示设备状态（功率、转速）
Thermometer（温度计）温度计样式液柱高度表示数值大小温度显示（很直观）
Tank（液罐）液罐/水槽样式填充高度表示数值液位显示、容量显示
Meter（表头）弧形表头指针+刻度，类似万用表模拟真实仪表的读数
数值控件的默认数据类型是 DBL（双精度浮点数），支持小数。如果想限制为整数，右键控件 → Representation → 选择 I32 或其他整数类型。

5.2 布尔控件（Boolean）—— 开关和指示灯

布尔控件只有两个状态：True（真/开） 和 False（假/关）。

控件外观机械动作典型用途
Push Button方形按钮按下为True，松开回弹为False触发动作：「开始测试」、「保存数据」
Toggle Switch拨动开关拨到一边为True，另一边为False，保持状态模式选择：「手动/自动」、「充电/放电」
Round LED圆形指示灯只能显示，不可点击（Indicator类型）状态指示：「运行中」绿灯、「故障」红灯
Stop Button红色方形停止按钮按下为True程序停止按钮
OK Button绿色勾按钮按下为True，松开为False确认/确定按钮

🔑 布尔控件的「机械动作」（Mechanical Action）

右键布尔控件 → Mechanical Action，有 6 种模式。最重要的是理解两种：
Latch When Released（松开时复位）：按下→松手→触发一次True→自动回到False。适合「开始测试」按钮。
Switch When Pressed（按下时切换）：按一下变 True，再按一下变 False，保持状态。适合「启用/禁用」开关。
错误用法：给 Stop 按钮选了 Switch 模式 → 用户按了一次停止后，停止端子一直是 True，下次运行程序立刻停止。Stop 按钮必须用 Latch 模式！

5.3 字符串控件（String）—— 文本的输入和显示

  • String Control：用户输入文本，如备注、密码、通信命令
  • String Indicator：显示文本，如通信返回数据、日志信息
  • Combo Box：下拉选择框，用户从预设列表中选择

右键字符串控件可以切换显示模式：Normal Display（正常）、\ Codes Display（显示换行符等）、Password Display（密码星号）、Hex Display（十六进制）。

5.4 路径控件（Path）

File Path Control 用于让用户选择文件或文件夹路径。点击旁边的文件夹图标可以浏览选择。在程序框图中，路径可以传给文件读写函数。

5.5 装饰控件（Decorations）—— 让界面更专业

在前面板右键 → Decorations，可以放置线条、矩形框、文本标签。这些元素不参与程序逻辑，纯粹用于界面美观。用矩形框把相关控件圈起来，加上分类标签，界面立刻变专业。

6.2 布尔类型（Boolean）

  • 只有两个值：True（真）和 False（假）
  • 连线颜色：🟢 绿色
  • 在内部存储为 8 位（1 字节），但逻辑上只有两个状态
  • 布尔运算：AND（与）、OR（或）、NOT（非）、XOR（异或）、NAND、NOR、Implies
  • Select 函数：根据布尔值选择输出——True 输出上端子的值，False 输出下端子的值。相当于 C 语言的三元运算符 cond ? a : b

6.3 字符串类型（String）

  • 连线颜色：💗 粉色
  • 用于存储和操作文本数据
  • 常用操作：拼接（Concatenate）、截取子串（String Subset）、查找替换（Search and Replace）、格式化（Format Into String）、字符串↔数值互转（String To Number / Number To String）
  • Format Into String 是格式化神器：把数值格式化成指定精度的字符串。比如 3.1415926 格式化成 "3.14"

6.4 枚举类型（Enum）

枚举是自定义的有限选项列表。这是提升代码可读性的利器。

  • 在前面板放置 Enum 控件 → 右键 → Edit Items → 添加选项
  • 例如定义「测试状态」枚举：空闲、充电中、放电中、暂停、完成、故障
  • 在程序框图中，Enum 端子是蓝色（类似整数），配合 Case 结构使用，每个枚举值对应一个 Case 分支
  • 用枚举而不用整数 0/1/2 的好处：代码可读性极高，修改时自动更新所有使用处

6.5 时间戳（Timestamp）

  • LabVIEW 的内置时间类型，精确到毫秒甚至更高
  • 获取当前时间：右键 → Timing → Get Date/Time In Seconds
  • 格式化显示：Format Date/Time String 函数

6.6 动态数据类型（Dynamic Data Type）

深蓝色粗线，由 DAQ Assistant 和 Express VI 产生。初学者会接触到，但随着水平提高应该尽量避免使用，转而使用明确的数据类型（数组+波形）。

🔗 连线与数据流：LabVIEW 程序怎么「运行」

▼

7.1 数据流编程：LabVIEW 最核心的概念（没有之一）

🔑 数据流执行规则（读三遍！）

规则：一个节点（函数/子VI）只有在它的所有输入端都收到数据之后才开始执行。
这意味着：

  • 如果 A 的输出连到了 B 的输入 → A 一定先于 B 执行（数据依赖决定顺序）
  • 如果 C 和 D 的输入彼此独立、没有连线关系 → C 和 D 同时并行执行（天然多线程）

这和文本编程完全不同。在 C 语言里，代码从上到下顺序执行，你想并行必须手动创建线程。在 LabVIEW 里，只要两个函数没有数据依赖关系，就自动并行跑。

7.2 连线规则详解

规则说明
一个输出可连多个输入一个数据源可以分叉（Branch）连到多个接收端，这叫「分支」
一个输入只能有一个来源一个输入端只能接一根线。不能两路数据同时输入同一个端子
数据类型必须匹配橙色（DBL）不能直接连蓝色（I32）端子，需要转换函数
不能形成闭环数据不能循环依赖——A→B→C→A 是不允许的。循环只能通过结构实现

7.3 如何控制执行顺序？

既然 LabVIEW 是数据流驱动，那怎么保证 A 在 B 之前执行（即使它们没有数据依赖）？

✅ 推荐方式：错误簇串联

把 A 的 Error Out 连到 B 的 Error In。错误簇形成了一个「逻辑传递链」，强制顺序。同时实现了错误处理——双重好处。

// 正确写法：用Error簇控制顺序
子VI_A.vi ──Error Out──→ 子VI_B.vi ──Error Out──→ 子VI_C.vi
    │                       │                       │
    └──数据──┘               └──数据──┘

❌ 不推荐：Flat Sequence 结构

把 A 放在第 0 帧，B 放在第 1 帧。虽然能强制顺序，但破坏了并行性，让代码变得僵硬。只在真正需要时使用（如确保界面更新后再执行某操作）。

// 可以但不推荐
[Frame 0: 子VI_A] → [Frame 1: 子VI_B]
// 问题：即使B和A没有实际依赖，B也必须等A完成

7.4 常见连线错误及解决方法

问题原因解决
黑色虚线（断线）数据类型不匹配检查两端类型，添加类型转换函数。Ctrl+B 清除断线
红色小三角数值类型自动转换（如 I32→DBL）不一定需要改，但要注意可能的精度损失
Run 箭头断裂程序框图有错误点击断裂箭头查看错误列表，逐一修复
线太乱没有整理右键空白处 → Clean Up Diagram，或手动整理
连线绕一大圈控件位置不合理移动控件让输入端在左边、输出端在右边，形成从左到右的数据流
程序框图应该从左到右阅读，数据从左向右流动。养成这个习惯，你的代码别人一眼就能看懂。

🔁 程序控制结构：循环、条件、事件

▼

8.1 For 循环 —— 重复执行 N 次

For 循环有两个关键端子：N（循环总次数，左上角）和 i（当前迭代计数，从0开始，左下角）。

📌 示例：计算 1+2+3+...+100 的和
┌─ For Loop ────────────────┐
│ N = 100（常量）             │
│ 左侧移位寄存器初值 = 0       │
│ 循环体：移位寄存器 + (i+1) →  │
│         写入右侧移位寄存器    │
│ 右侧移位寄存器输出 = 5050     │
└───────────────────────────┘

🔑 自动索引（Auto-Indexing）—— For 循环最重要的特性

当数组从外部接入 For 循环时，隧道默认开启自动索引：数组被逐元素「拆开」，每次循环处理一个元素。输出隧道也会自动把每次循环的结果「组装」回数组。
右键隧道可以切换模式：自动索引（有 [] 图标）、最后值（只有最后一次的值）、条件（只有满足条件时才输出值）。

8.2 While 循环 —— 直到条件满足才停

For 循环While 循环
停止条件达到 N 次条件端子为 True 时停止（可设置）
至少执行0 次（如果 N=0）至少 1 次（先执行再判断）
典型场景遍历数组、重复固定次数等待用户停止、持续采集、事件监听
While 循环至少执行一次！这意味着即使你的停止条件一开始就为 True，循环也会先跑一轮再退出。如果这是一个致命问题，考虑用 For 循环或在循环体内加判断。

8.3 Case 结构（条件结构）—— 根据条件走不同分支

Case 结构相当于 if-else 或 switch。顶部的 ? 选择器端子 决定执行哪个分支。

  • 选择器接布尔值 → True / False 两个分支 → 相当于 if-else
  • 选择器接整数 → 0, 1, 2, 3... 多个分支 → 相当于 switch
  • 选择器接字符串 → "充电", "放电", "空闲"... → 非常灵活
  • 选择器接枚举 → 每个枚举值一个分支 → 最推荐！清晰且安全
始终设置一个 Default 分支（右键分支标签 → Make This Case Default）。如果选择器值没有匹配的分支，会走 Default，避免程序出错。

8.4 Event 结构（事件结构）—— UI 编程的核心

Event 结构等待某个事件发生（用户点击按钮、修改数值、按键、关闭窗口等），然后执行对应的处理代码。

📌 Event结构的标准模板：
While 循环 ─────────────────────────────
  │
  └─ Event 结构
       ├─ "开始测试": Value Change → 启动测试流程
       ├─ "停止": Value Change → 停止采集并保存
       ├─ Timeout（100ms） → 更新实时数据显示
       └─ "前面板关闭": Panel Close? → 清理退出
黄金规则：Event 结构必须放在 While 循环内部！单独的 Event 结构只处理一个事件就结束了。放在 While 循环里才能持续监听。

8.5 移位寄存器（Shift Register）—— 循环间的「记忆」

在循环边框右键 → Add Shift Register，出现两个小三角：

  • 左侧 ↓ 箭头：上一次迭代的输出值，第一次迭代用初始值
  • 右侧 ↑ 箭头：本次迭代的值，传给下一次迭代
  • 拖动下边框可以增加端子，变成多层移位寄存器，保留前 N 次的值

经典应用：

  • 累加器（初始值 0，每次加当前值）
  • 求最大值（初始值 -∞，每次比较取大值）
  • 数据缓冲区（保留最近 10 次的数据）
  • 状态机（存储当前状态枚举）

8.6 公式节点（Formula Node）

如果要对数值做复杂的数学运算，用一堆算术函数连线会很乱。公式节点让你直接写类似 C 语言的数学表达式。

// 公式节点示例：计算 y = a*x^2 + b*x + c
float y;
y = a*x*x + b*x + c;

输入变量 a、b、x 在左边框创建，输出变量 y 在右边框创建。

9.1 数组（Array）

数组是相同类型数据的集合。LabVIEW 中用粗边框表示数组数据。

创建数组的方法：

  1. 在前面板：先放置一个 Array 壳（Array, Matrix & Cluster → Array），再拖一个控件放进去。壳 + 内容 = 数组控件
  2. 在程序框图：用 Build Array 把多个元素合并为数组

核心数组函数：

函数功能输入输出
Build Array合并元素或数组多个元素/数组合并后的数组。右键可选择合并模式
Index Array提取指定位置的元素数组 + 索引该索引处的元素值
Replace Array Subset替换指定位置的元素数组 + 索引 + 新值修改后的数组（原数组不变）
Delete From Array删除元素数组 + 索引缩短的数组
Array Size获取数组长度数组1D数组→1个数，2D数组→2个数
Search 1D Array搜索元素索引数组 + 搜索值索引（找不到返回-1）
Sort 1D Array升序排序数组排序后数组
Initialize Array创建指定大小的初始化数组元素值 + 维度大小填充好的数组

9.2 簇（Cluster）

簇是把不同类型数据打包在一起的结构。类似 C 语言的 struct。

📌 簇的典型例子——测试结果包：
┌── Cluster（测试结果）────────┐
│  电压 (DBL)：3.85 V          │
│  电流 (DBL)：1.25 A          │
│  温度 (DBL)：28.5 ℃          │
│  记录时间 (Timestamp)        │
│  状态 (Enum)：充电中          │
└─────────────────────────────┘

核心簇函数：

  • Bundle（打包）：按顺序把数据打包成簇。输入端子顺序要和簇定义顺序一致
  • Unbundle（解包）：按顺序取出簇中所有元素
  • Bundle By Name（按名称打包）：按名称打包，不依赖顺序 —— 强烈推荐！
  • Unbundle By Name（按名称解包）：按名称提取单个元素 —— 最常用
定义簇时给每个元素起好名字（在前面板编辑标签），在程序框图中用 Bundle By Name / Unbundle By Name，代码清晰又安全。

📈 图表与显示：把数据变成可视化

▼

10.1 Waveform Chart vs Waveform Graph

这是初学者最容易混淆的概念，务必搞清楚：

特性Waveform Chart（波形图表）Waveform Graph（波形图）
数据方式每次写入一个点，追加到历史数据后面一次性写入整个数组
内部缓冲区✅ 有（默认保存1024个历史点）❌ 没有
X轴自动递增（时间点）从0开始的索引
适用场景实时采集——每秒采一个点，持续显示趋势事后分析——采集完成后显示完整波形
写入方式每次循环写入当前值（一个标量）把整个数组一次写入

🔑 记住：

Chart = 实时滚动显示（Real-time scrolling），数据点一个一个追加 → 适合采集过程中实时观察
Graph = 一次性绘图（One-shot plot），把整个数组画出来 → 适合采集完成后展示分析

10.2 XY Graph —— 画 X-Y 关系曲线

普通的 Graph 的 X 轴是均匀间隔的（0, 1, 2, 3...）。XY Graph 允许你自定义 X 值，画任意 X-Y 关系。典型应用：I-V 特性曲线、李沙育图形、电池充放电曲线（电压 vs 容量）。

10.3 多曲线显示

在一个 Chart/Graph 上显示多条曲线：

  • Chart 多曲线：用 Bundle 函数把多个数据合并，一条数据对应一条曲线
  • Graph 多曲线：用 Build Array 把多个一维数组合并成二维数组，每行一条曲线

🧱 子 VI 与模块化：写出可复用的代码

▼

11.1 什么是子 VI？

子 VI 就是 LabVIEW 中的「函数」。把一段常用功能封装成一个 VI，在任何地方拖入调用。类比：

  • Python: def function_name(): ...
  • C: void function_name() { ... }
  • LabVIEW: 创建一个 VI，用连接器定义输入输出

11.2 创建子 VI 的完整步骤

  1. 写好功能代码：在一个普通 VI 中把功能调通（如把摄氏度转华氏度的公式写成VI）
  2. 定义连接器（Connector Pane）：前面板右上角小图标右键 → Show Connector。选择一个端子布局模式。标准布局：4-2-2-4（上下各4个，左右各2个）。分配原则：左上=输入，右上=输出，左下=Error In，右下=Error Out。
  3. 分配端子：点击连接器的一个格子（会变黑），再点击前面板上对应的控件/显示件。格子颜色变化表示已绑定。输入格子=橙色，输出格子=棕色。
  4. 设计图标：右上角图标右键 → Edit Icon。用4-6个字概括功能+简单色块。好图标让代码一看就懂。
  5. 设置 VI 属性：File → VI Properties → Documentation，写清楚这个 VI 做什么。当别人把鼠标悬停在这个子 VI 上时，Ctrl+H 会显示这段描述。
  6. 保存：保存到项目文件夹。文件名要有意义，如 "Convert_C_to_F.vi"。

11.3 子 VI 设计铁律（违背这些就是不合格的子 VI）

  1. 必须有 Error In / Error Out：没有任何例外。这是 LabVIEW 世界的通信协议
  2. 单一职责：一个子 VI 只做一件事。名字里有「和」字说明该拆成两个
  3. 有意义的文件名：Get_Temperature.vi，而不是 subvi_03.vi
  4. 输入端给默认值：让子 VI 即使没接输入也能正常运行
  5. 写 VI Description：别人用 Ctrl+H 看你的子 VI 时能看到说明

🔍 调试与错误处理：写出可靠的程序

▼

13.1 错误簇 —— LabVIEW 的「神经系统」

错误簇包含三个字段：Status（布尔，True=有错）、Code（整数，错误码，0=无错）、Source（字符串，错误来源描述）。

🔑 错误处理链的运作机制：

子 VI A 的 Error Out → 子 VI B 的 Error In → 子 VI B 的 Error Out → 子 VI C 的 Error In ...
如果 A 出错了：A 的 Error Out 的 Status=True → B 检测到 Error In 有错 → B 内部跳过所有操作（不做任何事）→ 错误从 B 的 Error Out 原封不动传出 → C 同样跳过 → 最终在顶层被 Simple Error Handler 弹窗显示。

13.2 调试三神器（必须学会）

  1. 💡 探针（Probe）：在连线上右键 → Probe。打开探针窗口，实时显示该连线的数据值。不需要改任何代码，不需要停止程序。
  2. 🔦 高亮执行（灯泡按钮）：点击工具栏的💡灯泡。数据以动画气泡沿着连线缓慢流动，直观看到数据流向和每个节点的执行顺序。适合「我不知道程序在干什么」的时候。
  3. ⏸ 断点（Breakpoint）：在节点或连线上右键 → Set Breakpoint。程序运行到此处自动暂停，你可以检查所有变量的值、堆栈状态。适合「程序在某个地方崩了但我不知道在哪」的时候。

13.3 常见错误排查指南

现象可能原因排查方法
Run箭头断裂（齿轮图标）有断线、必填端子未接、子VI找不到点击断裂箭头查看错误列表
程序运行但没有反应Event 结构没放 While 循环里、条件端子一直不满足用高亮执行看程序走到哪了
数据值不对连线连错了端子、类型转换丢失精度放探针看每段线的实际值
程序越跑越慢到最后崩溃内存泄漏：循环中不断创建新数组/新引用不释放任务管理器看内存使用，检查循环中是否有 Build Array 在累积
界面卡死在 Event 结构中放了耗时操作（仪器通信、长时间等待）改用生产者-消费者模式，Event只负责发消息

🔌 串口与仪器通信：让 LabVIEW 和硬件对话

▼

14.1 VISA —— 统一 I/O 接口

VISA（Virtual Instrument Software Architecture）是 NI 的统一通信接口。一套函数，搞定串口、GPIB、USB、以太网所有通信方式。

14.2 串口通信五步法（最重要！电池测试中天天用）

  1. VISA Open（打开端口）：VISA resource name = "COM3"（串口号）。返回 VISA 会话句柄
  2. VISA Configure Serial Port（配置参数）：设置波特率（Baud Rate，如 9600/19200/38400/115200）、数据位（Data Bits，通常 8）、停止位（Stop Bits，通常 1.0）、校验（Parity，通常 None）、流控（Flow Control，通常 None）
  3. VISA Write（发送命令）：把字符串命令发送到仪器。如发送 "*IDN?\n" 查询仪器身份
  4. VISA Read（读取返回数据）：读取仪器的响应。读取前用 Bytes at Serial Port 检查缓存中有多少字节，再读那么多
  5. VISA Close（关闭端口）：必须！不关的话端口一直被占用，下次打不开
📌 串口通信的完整代码模式：
VISA Open("COM3") ──→ VISA Config(9600,8,1,None,None)
   ──→ VISA Write("*IDN?\n")
   ──→ Wait(100ms) // 等仪器响应
   ──→ Bytes at Port → VISA Read(N字节)
   ──→ VISA Close
所有步骤的 Error 簇串联
串口调试最常见问题：波特率不匹配、COM口号不对、忘记 VISA Close 导致端口占用、Read 之前没有等仪器响应。建议先用 SSCOM 等通用串口工具确认硬件通信正常，再用 LabVIEW 写程序。

14.3 SCPI 命令 —— 仪器的「通用语言」

大多数程控仪器都支持 SCPI（Standard Commands for Programmable Instruments）命令：

命令功能示例
*IDN?查询仪器身份（型号、序列号）返回 "KEYSIGHT,34465A,MY12345678"
*RST复位到默认状态—
MEAS:VOLT:DC?测量直流电压返回 "5.234"（5.234V）
SOUR:VOLT 5.0设置输出电压为 5V—
OUTP ON开启输出—

🏗 设计模式：从「能跑」到「专业」

▼

15.1 状态机（State Machine）—— 90% 程序的首选架构

状态机 = While循环 + Case结构 + 移位寄存器（存储当前状态枚举）。

📌 电池充电测试的状态机：
Initialize（初始化仪器）
  → Idle（等待用户点开始）
    → CC_Charge（恒流充电：监控电压直到达到阈值）
      → CV_Charge（恒压充电：监控电流直到降到截止电流）
        → Rest（静置30秒）
          → Measure（测量并记录数据）
            → Check（判断：还有下一轮循环？→ CC_Charge / 完成？→ Done）
              → Save（保存数据）
                → Done（停止）
用 枚举类型 来定义状态（而不是用整数0/1/2），每个状态的名字一目了然。修改流程只需改变 Case 中写入的「下一个状态」枚举值。

15.2 生产者-消费者模式 —— 解决界面卡顿的终极方案

两个并行循环通过队列（Queue）通信：

  • 生产者（UI循环）：处理用户操作（Event结构），把「命令」通过队列发给消费者。响应极快，从不卡顿
  • 消费者（工作循环）：从队列取命令，执行耗时任务（仪器通信、数据采集、文件保存）
这就是工业级 LabVIEW 程序不卡顿的秘密。任何一个「正经」的 LabVIEW 程序都应该使用这个模式。

15.3 QMH（Queued Message Handler）—— 工业界标准

QMH = 队列 + 状态机 + 事件驱动。每条「消息」是一个字符串命令 + 可选数据：

  • 消息格式：用簇打包 {命令字符串, 数据 Variant}
  • 消费者中的 Case 结构根据命令字符串分发处理
  • 可扩展多个消费者（采集消费者、显示消费者、存储消费者）

16.1 项目需求

搭建一个电池充放电自动测试系统：

  • 控制程控电源（充电）和电子负载（放电）

  • 自动计算电池容量（Ah）、能量（Wh）、效率
  • 数据保存为 CSV 和 TDMS 格式
  • 用户可设置测试参数（充电电压、充电电流、放电电流、截止条件）

16.3 开发步骤

  1. 需求文档：和客户/领导确认测试参数、精度要求、报告格式，写下来双方确认
  2. 硬件选型：电源型号、电子负载型号、DAQ采集卡型号、通信协议（RS-232/GPIB/LAN）
  3. 架构设计：选择 QMH 架构，画消息流程图，定义所有消息类型
  4. UI 设计：前面板分区设计——参数设置区（左）、实时数据显示区（中）、曲线区（右）、控制按钮区（底）
  5. 底层驱动开发：分别写出电源控制子VI（设置电压/电流/输出开关）、电子负载控制子VI（设置CC/CV/CR/CP模式）、DAQ采集子VI
  6. 核心逻辑开发：实现状态机流程（Idle→CC_Charge→CV_Charge→Rest→CC_Discharge→CheckLoop）
  7. 数据处理：实时计算容量（积分电流×时间）、能量、效率；异常检测（过压/过流/过温保护）
  8. 数据存储：CSV（方便Excel查看）+ TDMS（快速存储+属性标注）
  9. 测试验证：先用模拟数据跑通全流程，再连接真实硬件逐步测试
  10. 发布打包：生成 EXE + 安装包（含 Run-Time Engine），编写用户操作手册
