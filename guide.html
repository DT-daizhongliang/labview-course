🔰 认识 LabVIEW：它是什么，为什么用它

▼

1.1 LabVIEW 是什么？

LabVIEW（Laboratory Virtual Instrument Engineering Workbench）是由美国国家仪器公司（NI）开发的图形化编程平台。与传统的文本编程语言（如 C、Python）不同，LabVIEW 用图形、连线和图标代替文字代码来编写程序。

💡 类比理解：如果把 C 语言比作「写作文」（用文字表达逻辑），那 LabVIEW 就是「画流程图」（用图形表达逻辑）。你不需要记忆语法规则，只需要把功能方块用线连起来即可。

1.2 LabVIEW 用在什么地方？

领域具体应用为什么用 LabVIEW
🔋 电池测试充放电循环测试、容量标定、内阻测量天生适合与仪器通信，自带数据采集和图表显示
🏭 产线自动化ATE 自动化测试站、质量检测快速开发，硬件驱动丰富
🔬 实验室测量温度/压力/振动/电压采集与分析直接读取传感器数据，实时波形显示
🤖 运动控制电机控制、机械臂、伺服系统NI 运动控制卡配合使用
📡 仪器程控程控电源、万用表、示波器、电子负载VISA 统一接口，SCPI 命令编程

1.3 LabVIEW 的三大核心思想

🎨 图形化编程

用「前面板」做界面 +「程序框图」写逻辑。没有一行文字代码，全是看得见的线和图标。

⚡ 数据流驱动

节点在所有输入数据到齐后才执行。多个独立节点自动并行运行，无需手动写多线程代码。

🧱 模块化思维

任何 VI 都可以变成「子 VI」，像搭积木一样组合。一个复杂项目 = 几十个简单子 VI 的组合。

⚡ 数据流编程：LabVIEW 最核心的概念

▼

3.1 什么是数据流？

在文本编程语言中，代码从上到下一行一行执行。在 LabVIEW 中，一个节点在其所有输入端都收到数据时才执行。这是理解 LabVIEW 最最关键的一点。

💡 通俗理解：把每个函数想象成一个工人。工人只有在「所有原材料都到齐」后才开始干活。多个工人如果原材料互不依赖，就同时干活（自动并行）。

3.2 连线：数据的「公路」

连线是数据在程序框图中流动的路径。不同颜色和粗细代表不同的数据类型：

颜色线型数据类型说明
🟠 橙色细线浮点数 DBL小数，最常用（如 3.14、-27.5）
🔵 蓝色细线整数 I32整数（如 0、100、-5）
🟢 绿色细线布尔值只有 True 或 False
🩷 粉色细线字符串文本数据
⚫ 黑色虚线虚线❌ 断线数据类型不匹配，连接错误
⚠ 看到虚线怎么办？说明你连错了——两个端子的数据类型不匹配。按 Ctrl+B 一键删除虚线，然后检查两端的类型是否一致。

3.3 创建你的第一个 VI：A + B = C

1

新建 VI

在 Getting Started 窗口点击 New VI，或按 Ctrl+N。

2

在前面板放控件

灰色窗口右键 → Numeric → Numeric Control（输入框，放两个）→ Numeric → Numeric Indicator（显示框，放一个）。

3

切换到程序框图

按 Ctrl+E 切到白色窗口，你会看到三个图标对应刚才放的控件。

4

添加加法函数

白色窗口右键 → Numeric → Add，鼠标变成小手，点一下放置。

5

连线

鼠标移到图标的小端子上（会变成线轴图标），按住拖到另一个端子，完成连线。把两个输入连到 Add 的 x 和 y，Add 的输出连到显示框。

6

运行

按 Ctrl+R 或点击工具栏的 ▶ 白色箭头。在前面板的输入框里输入数字，结果自动计算。

🎉 恭喜！你已经写完了你的第一个 LabVIEW 程序。这个 VI 做的事 = 两个输入相加，显示结果。虽然简单，但包含了创建控件 → 添加函数 → 连线 → 运行的完整流程。

3.4 数据流的执行顺序规则

  1. 有依赖就按依赖走：如果 A 的输出连到 B 的输入，A 一定先于 B 执行
  2. 无依赖就并行跑：两个节点之间没有连线关系，就同时执行（多核 CPU 自动利用）
  3. 用错误簇控制顺序：想让不相关的节点按顺序执行？把 Error Out → Error In 串起来
  4. 顺序结构慎用：Flat Sequence 强制顺序，但破坏了并行性，能不用就不用
💡 经验之谈：初学者容易过度使用顺序结构。正确做法是：让数据依赖自然决定执行顺序，Error 簇辅助控制。只有真正需要「先做 A 再做 B」且两者没有数据依赖时才用顺序结构。

4.2 字符串（String）—— 文本数据的处理

字符串在 LabVIEW 中有四种显示模式（右键控件切换）：

  • Normal Display（正常显示）：普通文本，如 "Hello World"
  • \ Codes Display（代码显示）：显示转义字符，如换行 \n、制表 \t
  • Password Display（密码显示）：显示为 ******
  • Hex Display（十六进制显示）：显示为字节的十六进制值

常用字符串函数（在程序框图右键 → String 子选板）：

函数功能示例
Concatenate Strings拼接多个字符串"Hello " + "World" → "Hello World"
String Subset截取子串"ABCDEF", offset=2, length=3 → "CDE"
Search and Replace查找替换把 "A" 全部替换为 "X"

4.3 枚举（Enum）—— 限定选项的利器

枚举是有限个选项的列表。比如用枚举定义测试状态：

  1. 在前面板上放置 Enum 控件（右键 → List & Table → Enum）
  2. 右键 → Edit Items，添加选项：空闲、充电中、放电中、暂停、完成、故障
  3. 在程序框图中，用 Case 结构根据枚举值执行不同逻辑
💡 为什么用枚举而不用整数：用 0/1/2 表示状态，别人看不懂你的代码。用枚举，每个状态都有名字，可读性极高。修改枚举时会自动更新所有使用处。

🔁 程序结构：让你的代码「聪明」起来

▼

5.1 For 循环 —— 做 N 次重复的事

For 循环有 N 端子（循环总次数）和 i 端子（当前是第几次，从0开始）。

📌 典型用法 1：执行 10 次 N 端子接常量 10 → 循环体执行 10 次 📌 典型用法 2：遍历数组（自动索引） 数组从外面接入 For 循环 → 自动每次取出一个元素 → 处理完自动组装成数组输出 📌 典型用法 3：移位寄存器累加 循环边框右键 → Add Shift Register → 左侧端子初始值 0 → 右侧接 i → 最终左侧输出 = 0+1+2+...+9 = 45
💡 自动索引（Auto-indexing）：For 循环的隧道默认开启自动索引。输入数组会被「拆开」逐元素进入，输出隧道自动「组装」成数组。右键隧道可以切换模式。

5.2 While 循环 —— 直到条件满足才停

While 循环和 For 循环的区别只有一个：For 循环知道要循环多少次，While 循环不知道，靠条件判断。

For 循环While 循环
停止条件达到 N 次条件端子为 True（或 False，可设置）
最少执行次数0 次（N=0）至少 1 次（先执行再判断）
典型场景遍历数组、重复 N 次等待用户点击停止、持续采集
⚠ While 循环陷阱：While 循环至少执行一次！如果你设置「Stop if True」但忘记给停止按钮初始值，可能导致无限循环。养成在停止条件前加超时保护的习惯。

5.3 Case 结构（条件结构） —— 根据条件走不同分支

Case 结构相当于文本编程中的 if-else 或 switch-case。顶部的 ? 选择器端子决定走哪个分支。

  • 选择器接布尔值 → 两个分支：True / False
  • 选择器接整数 → 多个分支：0, 1, 2, 3...
  • 选择器接字符串 → 多个分支："充电", "放电", "空闲"...
  • 选择器接枚举 → 每个枚举值一个分支（最推荐！）
💡 最佳实践：始终让 Case 结构有一个 Default 分支（右键分支标签 → Make This Case Default）。这样即使出现意外的选择器值也不会出错。

5.4 Event 结构（事件结构） —— 响应用户操作

Event 结构是 LabVIEW UI 编程的核心。它「等待」用户操作（点击按钮、修改数值、按键等），然后执行对应的处理代码。

📌 Event 结构的标准使用模式： While 循环内放 Event 结构 ├── "开始测试": Value Change → 启动测试序列 ├── "停止": Value Change → 停止并保存数据 ├── "超时": Timeout → 更新实时数据显示（每100ms刷新） └── "前面板关闭": Panel Close? → 清理资源并退出
⚠ 黄金规则：Event 结构必须放在 While 循环内部！单独一个 Event 结构只会执行一次（处理一个事件后就结束了）。放在 While 循环里才能持续监听事件。

5.5 移位寄存器（Shift Register） —— 循环间的「记忆」

移位寄存器是 LabVIEW 中最精妙的设计之一。它让循环可以「记住」上一次迭代的数据。

  • 在循环边框 右键 → Add Shift Register
  • 左侧 ↓ 箭头 = 上一次迭代的输出（第一次迭代用初始值）
  • 右侧 ↑ 箭头 = 本次迭代要传给下一次的值
  • 拖动下边框可以创建多层移位寄存器，同时记住前 N 次的值
💡 经典应用：移位寄存器实现累加器、滑动平均、状态机（存储当前状态枚举）、数据缓冲队列。几乎所有高级设计模式都依赖移位寄存器。

📦 数组与簇：批量处理数据的利器

▼

6.1 数组（Array） —— 同类数据的集合

数组是一组相同类型数据的集合。LabVIEW 中数组用粗边框表示，支持 1D（一维）、2D（二维）和多维。

操作函数说明
创建数组Build Array把多个元素或子数组合并。Concatenate Inputs 选项控制是「合并为元素」还是「拼接为长数组」
获取元素Index Array按索引取出元素。不接索引 = 取第 0 个。拖拽下边框可取多个元素
替换元素Replace Array Subset替换指定位置的元素，不改原数组（数据流原则）
删除元素Delete From Array删除指定位置元素，返回缩短的数组
数组大小Array Size返回数组长度。1D → 一个数，2D → 两个数（行数、列数）
搜索Search 1D Array搜索元素所在索引。找不到返回 -1
排序Sort 1D Array升序排列
初始化Initialize Array创建指定大小的数组，所有元素为同一个值

6.2 簇（Cluster） —— 不同类型数据的打包

簇是把不同类型的数据打包在一起。类似 C 语言的 struct 或 Python 的 tuple。

📌 簇的典型例子 —— 测试结果包： ┌─────────────────────────┐ │ Cluster（测试结果） │ │ ├── 电压 (DBL)：3.85 V │ │ ├── 电流 (DBL)：1.25 A │ │ ├── 温度 (DBL)：28.5 ℃ │ │ ├── 时间 (Timestamp) │ │ └── 状态 (Enum)：充电中 │ └─────────────────────────┘

关键函数：

  • Bundle（打包）：把独立数据打包成簇。端子顺序和簇定义顺序要一致
  • Unbundle（解包）：从簇中提取所有元素
  • Bundle By Name：按名称打包，不必按顺序 —— 推荐使用！代码更清晰
  • Unbundle By Name：按名称提取单个元素 —— 最常用
💡 最佳实践：定义簇时给每个元素起好名字（前面板编辑时输入标签）。这样在程序框图中就能用 Bundle By Name / Unbundle By Name，代码可读性大幅提升。

6.3 数组和簇的配合使用

实际项目中经常数组 + 簇混用：

  • 簇数组：每个元素是一个簇，如「多组测试数据」→ 每行是一个簇（电压+电流+温度）
  • 簇含数组：簇的某个字段是数组，如「测试配置」簇中包含「测试步骤列表」数组
  • 和表格控件配合：簇数组直接显示在多列列表框中

🧱 子 VI：模块化编程的核心技能

▼

7.1 什么是子 VI？为什么要用？

子 VI 就是 LabVIEW 的「函数」。把常用功能封装成子 VI，需要时直接调用，不用重复写代码。

💡 类比：如果你做了一个「摄氏转华氏」的功能，可能会在 20 个地方用到。不封装的话就要复制 20 次代码。封装成子 VI 后，20 个地方都调用同一个 VI，修改时只改一处。

7.2 创建子 VI 的标准步骤

1

写好功能

先在一个普通 VI 中把功能调通（如「温度转换.vi」）。

2

设计连接器窗格

右上角小图标右键 → Show Connector。选择一个模式（如 4-2-2-4）。标准规则：左上=输入，右上=输出，左下=Error In，右下=Error Out。

3

分配端子

用连线工具（线轴图标）点击连接器窗格的格子，再点击对应的控件/显示件，格子会变成输入或输出的颜色。

4

编辑图标

右键右上角图标 → Edit Icon。用 4-6 个字概括功能（如「C→F 转换」），配简单色块图形。

5

保存并调用

保存 VI。在其他 VI 的程序框图中，直接把 .vi 文件拖进去即可调用。

7.3 子 VI 设计规范（黄金法则）

  1. 必须有 Error In / Error Out：无一例外。这是 LabVIEW 世界的通行证
  2. 单一职责：一个子 VI 只做一件事。如果名字里出现了「和」字，就该拆成两个
  3. 有意义的文件名：Convert_C_to_F.vi，而不是 SubVI_01.vi
  4. 输入端加默认值：让子 VI 在没有输入数据时也能正常运行
  5. 加上 VI Description：File → VI Properties → Documentation，写清楚这个 VI 做什么
✅ 好的子 VI 示例：Read_Temperature.vi、Set_Power_Supply_Voltage.vi、Save_Data_To_TDMS.vi、Calculate_Battery_Capacity.vi —— 一看名字就知道做什么。

📌 读取 CSV（加载测试数据）： Read Delimited Spreadsheet.vi - file path：要读取的文件 - delimiter：和写入时一致 - 输出 all rows：二维字符串数组 → 需要转数值

8.3 TDMS —— NI 推荐的数据格式

TDMS（Technical Data Management Streaming）是 NI 为测试测量专门设计的二进制格式。它比 CSV 快 10-100 倍，同时保留结构化的属性描述。

📌 TDMS 结构： 文件(.tdms) ├── 通道组（Group）"电池1#" │ ├── 通道 "电压" ── [3.80, 3.82, 3.85, ...] │ ├── 通道 "电流" ── [1.20, 1.22, 1.19, ...] │ └── 属性 "测试人员" = "张三" └── 通道组（Group）"电池2#" └── ...
💡 为什么推荐 TDMS：① 读写速度快；② 文件小；③ 每个通道可加描述属性；④ NI DIAdem、DataFinder 等工具直接读取；⑤ 支持流式写入，采集过程中随时保存不丢数据。

9.1 调试三神器

💡 探针 Probe

在连线上右键 → Probe，打开探针窗口，实时显示该连线的当前值。不用改任何代码！

🔦 高亮执行

点击工具栏的💡灯泡按钮。数据以动画气泡沿着连线流动，直观看到数据流向和执行顺序。

⏸ 断点 Breakpoint

在节点或连线上右键 → Set Breakpoint。程序运行到此处自动暂停，检查所有变量的值。

9.2 错误簇 —— LabVIEW 的「神经系统」

错误簇包含三个字段：Status（布尔，是否出错）、Code（整数，错误码）、Source（字符串，错误来源）。

📌 错误处理的黄金法则： 每个子 VI 都有 Error In ──────────→ Error Out │ 如果 Error In 有错误 → 子 VI 内部 自动跳过所有操作 → 错误原封不动从 Error Out 传出 → 一级一级传到最后 → Simple Error Handler 弹窗提示用户
⚠ 常见错误：忘记把 Error 簇串联起来！如果几个子 VI 并行放置但 Error 线断了，其中一个出错其他还在执行，导致更严重的连锁错误。永远保持 Error 链完整。

9.3 自定义错误码

在自己的子 VI 中定义项目专属的错误码：

  • 建议范围：5000-9999（NI 保留 0-4999）
  • 用 Error Cluster From Error Code.vi 创建自定义错误
  • 在项目中统一维护一个错误码定义表（Excel 或文档）

🏗 设计模式：写出专业级代码

▼

10.1 状态机（State Machine）—— 最基础也最重要

状态机 = While 循环 + Case 结构 + 移位寄存器（存储当前状态枚举）。

📌 状态机模板： While 循环 ──────────────────────────────┐ │ │ ├─ Case 结构（选择器 = 移位寄存器的「当前状态」） │ │ ├─ "Initialize"：初始化仪器 → 下一状态 = "Idle" │ ├─ "Idle"：等待 → 用户点开始 → 下一状态 = "Run" │ ├─ "Run"：执行测试 → 完成 → 下一状态 = "Save" │ ├─ "Save"：保存数据 → 下一状态 = "Idle" │ ├─ "Stop"：清理资源 → While 停止 = True │ └─ "Error"：显示错误 → 下一状态 = "Stop" │ │ └─ 移位寄存器 ← 更新「下一个状态」 │ ──────────────────────────────────────────┘
💡 状态机适用场景：任何有明确步骤流程的程序——电池测试序列（初始化→CC充电→CV充电→静置→放电→循环判断→停止）、仪器自动校准、产线测试流程。

10.2 生产者-消费者模式 —— 界面不卡的秘诀

这是 LabVIEW 中解决「界面卡死」的王牌架构。

📌 两个并行循环通过「队列」通信： ┌─────────────────────┐ Queue ┌─────────────────────┐ │ 🔝 生产者循环 │ ───────────→ │ 🔽 消费者循环 │ │ (Event 结构) │ Enqueue │ (处理耗时任务) │ │ │ │ │ │ • 处理按钮点击 │ │ • 仪器通信 │ │ • 处理参数修改 │ │ • 数据采集 │ │ • 响应快（毫秒级） │ │ • 文件保存 │ │ • 不放耗时操作 │ │ • 数据处理 │ └─────────────────────┘ └─────────────────────┘
⚠ 为什么不用一个循环？如果把耗时操作放在 Event 结构的 Value Change 事件里，界面会「卡死」直到操作完成。生产者-消费者模式让 UI 永远响应流畅。

10.3 QMH（Queued Message Handler）—— 工业界标准架构

QMH = 队列 + 状态机 + 事件驱动。这是工业级 LabVIEW 项目的事实标准。

  • 每个「消息」是一个字符串命令（如 "Acquire", "Save", "Stop"）
  • 生产者把消息（可附带数据）Enqueue 到队列
  • 消费者 Dequeue 消息，用 Case 结构分发处理
  • 可扩展为多个消费者（一个采集、一个显示、一个存储）
🚀 进阶建议：先把状态机和生产者-消费者模式练熟，再学 QMH。这三个模式覆盖了 95% 的项目需求。

11.2 每个阶段的学习模板

⭐⭐⭐ 强烈建议使用「三步学习法」：

1

看范例（15分钟）

打开 Help → Find Examples，搜索相关关键词，运行官方范例，观察效果。

2

动手改（30分钟）

在范例基础上修改：改参数、加功能、换控件。改动是学习的最好方式。

3

独立写（1小时）

关掉范例，从空白 VI 开始自己写一遍。遇到不会的用 Ctrl+H 查帮助，不翻看之前的代码。

💡 学习心法：很多人看教程觉得「懂了」，但一上手就懵。原因是没有做第 3 步——独立写一遍。只有不看任何参考、从零写出来，才是真的学会了。

11.3 新手常见的 5 个坑（提前知道少走弯路）

  1. ❌ 过度使用顺序结构 → ✅ 用数据依赖和 Error 簇代替，让 LabVIEW 自然并行
  2. ❌ 所有代码堆在一个 VI 里 → ✅ 及时抽成子 VI，保持每个 VI 不超过一屏
  3. ❌ 忘记 Error In/Out → ✅ 每个子 VI 都必须有 Error 簇端子，这是铁律
  4. ❌ 用局部变量通信 → ✅ 用连线、移位寄存器、队列传递数据，避免竞态条件
  5. ❌ 前面板控件乱放 → ✅ 用对齐工具、统一间距、分类分区，界面就是产品质量的一部分

11.4 从「会写代码」到「能独立做项目」的跨越

会写代码 ≠ 会做项目。独立做项目需要额外掌握：

  • 需求分析：跟用户确认「到底要做什么」，写下来双方确认
  • 架构设计：先画结构图再编码，选对设计模式事半功倍
  • 版本管理：文件命名带日期版本（如 BatteryTest_v2.1_20260724.vi）
  • 测试方法：写 Simulation 模式的子 VI，没硬件也能测逻辑
  • 发布打包：生成 EXE + 安装包，用户不需要装 LabVIEW 就能运行
🎯 检验标准：当你能够
① 拿到需求 → ② 设计架构 → ③ 编写代码 → ④ 联调硬件 → ⑤ 测试通过 → ⑥ 打包发布
走完这 6 步，你就真正从「学习者」变成了「LabVIEW 工程师」。
